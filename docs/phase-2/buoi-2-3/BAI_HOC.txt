BUỔI 2.3 — Regularization L1/L2

HỌC SINH CẦN HIỂU
- Regularization thêm penalty nhằm hạn chế lời giải quá phức tạp theo giả định.
- L1 khuyến khích nhiều hệ số 0; L2 khuyến khích hệ số nhỏ.
- Độ mạnh regularization chọn bằng validation; scaling thay ý nghĩa penalty.

CÂU HỎI MỞ BÀI
Tại sao ta chấp nhận fit train kém hơn để hệ số bớt lớn?

VÍ DỤ VÀ CODE
Chạy python -X utf8 code_minh_hoa.py trong thư mục buổi. Notebook code_minh_hoa.ipynb có code và output đã chạy.
objective = data_loss + alpha × penalty

CẦN PHÂN BIỆT
Alpha và C ở các APIs có thể có chiều tác dụng ngược nhau.

THỰC HÀNH TRÊN LỚP

Bài trên lớp 1: Trả L1=sum|w| và L2_squared=sumw^2.
Input:
{
  "w": [
    1,
    -2,
    3
  ]
}
Output để đối chiếu sau khi làm:
{
  "l1": 6,
  "l2_squared": 14
}

Bài trên lớp 2: Không intercept: minimize sum(y-w*x)^2+alpha*w^2; w=sumxy/(sumx^2+alpha), denominator bằng 0→0.
Input:
{
  "x": [
    1,
    2
  ],
  "y": [
    2,
    4
  ],
  "alpha": 5
}
Output để đối chiếu sau khi làm:
1.0

BÀI VỀ NHÀ
- BTVN 1: Trả L1=sum|w| và L2_squared=sumw^2.; xem BTVN_01.txt.
- BTVN 2: Không intercept: minimize sum(y-w*x)^2+alpha*w^2; w=sumxy/(sumx^2+alpha), denominator bằng 0→0.; xem BTVN_02.txt.
- BTVN 3: Hồi quy có features nhiễu; xem BTVN_03.txt.
