# Code mẫu — Generalization

Khớp tốt dữ liệu cũ chưa đủ để đoán tốt trên mẫu mới. Ba thí nghiệm dưới đây lần lượt thay một nhãn, thay độ linh hoạt của model, và thay số mẫu train, để thấy mỗi phép kiểm trả lời một câu hỏi khác nhau.

## Ví dụ 1: Một nhãn ghi sai kéo dự đoán đi xa tới đâu?

Quy luật giả định là `y = x`. Train có bốn điểm ở `0, 2, 4, 6`, và ta thử ghi nhầm nhãn ở vị trí 4 thành 8. Cần dự đoán tại `x = 3.8`, nơi giá trị đúng theo quy luật là 3.8. kNN dự đoán bằng trung bình nhãn của các điểm gần nhất.

```python
import numpy as np
from sklearn.neighbors import KNeighborsRegressor

X_train = np.array([[0.0], [2.0], [4.0], [6.0]])
clean = np.array([0.0, 2.0, 4.0, 6.0])
noisy = np.array([0.0, 2.0, 8.0, 6.0])
query = np.array([[3.8]])
for k in [1, 3]:
    clean_model = KNeighborsRegressor(n_neighbors=k).fit(X_train, clean)
    noisy_model = KNeighborsRegressor(n_neighbors=k).fit(X_train, noisy)
    before = clean_model.predict(query)[0]
    after = noisy_model.predict(query)[0]
    train_mse = np.mean((noisy_model.predict(X_train) - noisy) ** 2)
    print(f"k={k}: trước={before:.3f}, sau={after:.3f}, đổi={after-before:.3f}, train MSE={train_mse:.3f}")
```

```output
k=1: trước=4.000, sau=8.000, đổi=4.000, train MSE=0.000
k=3: trước=4.000, sau=5.333, đổi=1.333, train MSE=5.111
```

Với một điểm gần nhất, nhãn sai lệch 4 đơn vị thì dự đoán cũng lệch đủ 4. Với ba điểm gần nhất, nhãn sai chỉ chiếm một phần ba, nên dự đoán chỉ lệch `4/3`. Train MSE của `k=1` bằng 0, nhưng con số ấy có được là nhờ model nhớ luôn cả nhãn 8 bị ghi sai. Lỗi train bằng 0 vì vậy chưa phải bằng chứng model đã tìm ra quy luật.

## Ví dụ 2: Cùng dữ liệu, ba mức linh hoạt

Dữ liệu giả lập theo `y = sin(2πx)` cộng thêm nhiễu có độ lệch chuẩn 0.2. Giá trị âm ở đây chỉ là mức lệch so với một mốc, không mang ý nghĩa gì đặc biệt. Train và validation được sinh riêng từ cùng một cơ chế, để so ba lựa chọn: `k=1`, `k=9`, và dùng cả 60 điểm làm hàng xóm.

```python
import numpy as np
from sklearn.neighbors import KNeighborsRegressor
from sklearn.metrics import mean_squared_error

rng = np.random.default_rng(121)
def sample(n):
    X = rng.uniform(0, 1, (n, 1))
    y = np.sin(2 * np.pi * X[:, 0]) + rng.normal(0, 0.2, n)
    return X, y

X_train, y_train = sample(60)
X_valid, y_valid = sample(180)
for k in [1, 9, 60]:
    model = KNeighborsRegressor(n_neighbors=k).fit(X_train, y_train)
    train_error = mean_squared_error(y_train, model.predict(X_train))
    valid_error = mean_squared_error(y_valid, model.predict(X_valid))
    print(f"k={k:2d}: train MSE={train_error:.4f}, valid MSE={valid_error:.4f}")

# Khi k bằng số điểm train và trọng số đều nhau, mọi truy vấn đều nhận cùng một giá trị là trung bình train.
flat = KNeighborsRegressor(n_neighbors=60).fit(X_train, y_train)
assert np.allclose(flat.predict([[0.1], [0.9]]), y_train.mean())
print("k=60 dự đoán hằng số:", round(float(y_train.mean()), 4))
```

```output
k= 1: train MSE=0.0000, valid MSE=0.0786
k= 9: train MSE=0.0442, valid MSE=0.0565
k=60: train MSE=0.5431, valid MSE=0.5491
k=60 dự đoán hằng số: -0.0253
```

Hãy so cột validation, vì cả ba model được chấm trên **cùng 180 mẫu**. `k=1` khớp train tuyệt đối, nhưng vẫn bám theo cả nhiễu, nên validation chưa phải tốt nhất. `k=60` thì quá cứng: nó luôn trả về một hằng số, nên mất hẳn hình sóng, và lỗi ở cả hai tập đều cao. `k=9` nằm giữa hai thái cực ấy và cho validation thấp nhất. Đó là kết quả của bộ dữ liệu này, không phải quy tắc chọn k dùng được cho mọi bài.

## Ví dụ 3: Learning curve thay đổi số mẫu, không thay đổi số epoch

Giữ nguyên `k=7`, rồi cho model học trên 21, 70 hoặc 210 mẫu trong mỗi fold. Dữ liệu vẫn là sóng sin cộng nhiễu 0.2. Chia thành bốn fold để xem xu hướng khi thêm dữ liệu, và mỗi lần fit chỉ dùng đúng phần train của fold ấy.

```python
import numpy as np
from sklearn.neighbors import KNeighborsRegressor
from sklearn.model_selection import KFold, learning_curve

rng = np.random.default_rng(122)
X = rng.uniform(0, 1, (280, 1))
y = np.sin(2 * np.pi * X[:, 0]) + rng.normal(0, 0.2, 280)
cv = KFold(n_splits=4, shuffle=True, random_state=122)
sizes, train_scores, valid_scores = learning_curve(
    KNeighborsRegressor(n_neighbors=7), X, y, cv=cv,
    train_sizes=[21, 70, 210], scoring="neg_mean_squared_error",
    shuffle=True, random_state=122, n_jobs=1,
)
for n, train, valid in zip(sizes, -train_scores.mean(axis=1), -valid_scores.mean(axis=1)):
    print(f"n={n:3d}: train MSE={train:.4f}, valid MSE={valid:.4f}")
print("Phương sai nhiễu giả:", round(0.2 ** 2, 4))
```

```output
n= 21: train MSE=0.0834, valid MSE=0.1082
n= 70: train MSE=0.0341, valid MSE=0.0502
n=210: train MSE=0.0314, valid MSE=0.0435
Phương sai nhiễu giả: 0.04
```

Mỗi dòng thay đổi **số mẫu train**, chứ không có epoch hay bước tối ưu nào trên trục này. scikit-learn trả về `neg_mean_squared_error`, tức MSE mang dấu âm, theo quy ước điểm càng lớn càng tốt, nên code đổi dấu lại để đọc lỗi cho dễ. Có thêm mẫu thì bảy hàng xóm nằm sát nhau hơn trên trục x, nên dự đoán bám xu hướng tốt hơn, và validation giảm từ 0.1082 xuống 0.0435. Mốc 0.04 là phương sai của nhiễu trong công thức sinh dữ liệu, tức mức lỗi không model nào vượt qua được. Validation trên một số mẫu hữu hạn có thể dao động quanh mốc ấy. Với dữ liệu thật, ta không biết trước mốc này.
