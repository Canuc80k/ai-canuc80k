# Code mẫu — BERT

Làm việc với BERT, có ba chuyện phải tách bạch: model được đọc những token nào, loss được tính ở những vị trí nào, và nhãn được gắn lên subword ra sao. Encoder nhỏ dưới đây được khởi tạo ngẫu nhiên để kiểm đường đi của thông tin. Nó chưa được pretrain, và không phải BERT pretrained.

## Ví dụ 1: Che chữ “đọc”, nhưng nhãn vẫn là “đọc”

Câu gốc là `An đọc sách PAD`. Ta chọn che đúng một vị trí, chữ “đọc”, cho một bước học kiểu MLM. MLM nghĩa là che một số token đi và bắt model đoán lại. Ở vị trí này, giả sử có ba lựa chọn là `đọc`, `viết`, `ngủ`. Logit được đặt bằng tay để tính loss đối chiếu, chứ không lấy từ một model đã học.

```python
import math
import torch
from torch import nn

torch.set_num_threads(1)
original = ["An", "đọc", "sách", "PAD"]
selected = torch.tensor([[False, True, False, False]])
corrupted = ["[MASK]" if chosen else token
             for token, chosen in zip(original, selected[0].tolist())]
labels = torch.tensor([[-100, 0, -100, -100]])
logits = torch.zeros(1, 4, 3)
logits[0, 1] = torch.tensor([2., 0., 0.])

def masked_loss(logits, labels):
    if not labels.ne(-100).any():
        raise ValueError("Không có vị trí MLM để tính loss")
    return nn.CrossEntropyLoss(ignore_index=-100)(
        logits.reshape(-1, 3), labels.reshape(-1))

loss = masked_loss(logits, labels)
probability = math.exp(2) / (math.exp(2) + 2)
print("input:", corrupted)
print("label:", labels.tolist())
print("số vị trí chấm:", int(labels.ne(-100).sum()))
print(f"p(đọc)={probability:.4f} loss={loss.item():.4f}")
assert math.isclose(loss.item(), -math.log(probability), abs_tol=1e-6)

changed = logits.clone()
changed[0, [0, 2, 3]] = torch.tensor([100., -100., 0.])
print("đổi logits vị trí bỏ qua, loss không đổi:", torch.allclose(loss, masked_loss(changed, labels)))
try:
    masked_loss(logits, torch.full_like(labels, -100))
except ValueError as error:
    print("bắt ca rỗng:", error)
```

```output
input: ['An', '[MASK]', 'sách', 'PAD']
label: [[-100, 0, -100, -100]]
số vị trí chấm: 1
p(đọc)=0.7870 loss=0.2395
đổi logits vị trí bỏ qua, loss không đổi: True
bắt ca rỗng: Không có vị trí MLM để tính loss
```

Đầu vào model thấy là `[MASK]` ở vị trí thứ hai, nhưng nhãn ở đó vẫn là 0, tức chữ “đọc”. Ba vị trí còn lại có nhãn −100, nghĩa là bỏ qua. Chúng không góp vào loss, và cũng không được đếm khi chia trung bình. Loss bằng $-\log\frac{e^2}{e^2+2}\approx0.2395$, tính trên đúng một vị trí, không chia thêm cho 4.

Đổi logit ở ba vị trí bị bỏ qua thành những giá trị rất lớn, loss vẫn y nguyên. Đó là cách kiểm rằng −100 thật sự hoạt động. Một batch không có vị trí nào được chọn sẽ khiến phép trung bình chia cho 0, nên hàm chặn trường hợp đó trước. Ví dụ này luôn thay token được chọn bằng `[MASK]`. BERT gốc còn có quy tắc riêng: trong các token được chọn, 80% thay bằng `[MASK]`, 10% thay bằng token ngẫu nhiên, và 10% giữ nguyên.

## Ví dụ 2: Đổi token bên phải để kiểm attention hai chiều

Hai câu có ID là `[1, 2, 3]` và `[1, 2, 4]`, chỉ khác token cuối. Một encoder một lớp, hai head, vector ẩn 8 chiều, xử lý cả hai câu. Ta không train gì. Câu hỏi duy nhất là: vector của token đầu có nhận thông tin từ token bên phải hay không?

```python
import torch
from torch import nn

torch.set_num_threads(1)
torch.manual_seed(63)
token_embedding = nn.Embedding(6, 8, padding_idx=0)
position_embedding = nn.Embedding(8, 8)
layer = nn.TransformerEncoderLayer(8, 2, dim_feedforward=16,
                                   dropout=0, batch_first=True)
encoder = nn.TransformerEncoder(layer, 1, enable_nested_tensor=False)
encoder.eval()

def encode(ids, causal=False):
    positions = torch.arange(ids.shape[1]).unsqueeze(0)
    inputs = token_embedding(ids) + position_embedding(positions)
    mask = None
    if causal:
        # True nghĩa là cấm query ở hàng i nhìn key ở cột j nằm phía sau.
        mask = torch.ones(ids.shape[1], ids.shape[1], dtype=torch.bool).triu(1)
    return encoder(inputs, mask=mask, src_key_padding_mask=ids.eq(0))

first = torch.tensor([[1, 2, 3]])
second = torch.tensor([[1, 2, 4]])
with torch.no_grad():
    bidirectional_a, bidirectional_b = encode(first), encode(second)
    causal_a, causal_b = encode(first, True), encode(second, True)
    padded = encode(torch.tensor([[1, 2, 3, 0, 0]]))
print("hidden shape:", tuple(bidirectional_a.shape))
print("hai chiều: token đầu đổi:", not torch.allclose(bidirectional_a[:, 0], bidirectional_b[:, 0]))
print("causal: tiền tố giữ nguyên:", torch.allclose(causal_a[:, :2], causal_b[:, :2], atol=1e-6))
print("thêm PAD: token thật giữ nguyên:", torch.allclose(bidirectional_a, padded[:, :3], atol=1e-6))
assert not torch.allclose(bidirectional_a[:, 0], bidirectional_b[:, 0])
assert torch.allclose(causal_a[:, :2], causal_b[:, :2], atol=1e-6)
assert torch.allclose(bidirectional_a, padded[:, :3], atol=1e-6)
```

```output
hidden shape: (1, 3, 8)
hai chiều: token đầu đổi: True
causal: tiền tố giữ nguyên: True
thêm PAD: token thật giữ nguyên: True
```

Ba phép thử, ba ý riêng. Với attention hai chiều như BERT, đổi token cuối làm vector của token đầu đổi theo, vì token đầu nhìn được cả bên phải. Với causal mask, hai token đầu giữ nguyên dù token cuối đổi, vì chúng không được nhìn về phía sau. Thêm PAD vào cuối câu, các token thật vẫn y nguyên, nhờ padding mask.

Cẩn thận với quy ước của mask. Trong `src_key_padding_mask` của PyTorch, `True` nghĩa là bỏ key đó. Còn `attention_mask` của Hugging Face thì ngược lại: 1 nghĩa là giữ. Lẫn hai quy ước là che nhầm token thật và giữ lại PAD.

Giờ thử gắn hai loại lớp đầu ra lên cùng các vector ẩn. Hai lớp này cũng khởi tạo ngẫu nhiên, nên ta chỉ xem shape, chưa đọc nhãn dự đoán.

```python
sequence_head = nn.Linear(8, 2)
token_head = nn.Linear(8, 3)
print("head câu:", tuple(sequence_head(bidirectional_a[:, 0]).shape))
print("head token:", tuple(token_head(bidirectional_a).shape))
```

```output
head câu: (1, 2)
head token: (1, 3, 3)
```

Lớp đầu ra cho cả câu chỉ đọc vector ở vị trí đầu, và cho một hàng hai lớp. Lớp đầu ra cho từng token đọc mọi vị trí, và cho ba hàng, mỗi hàng ba lớp. Trong BERT thật, vị trí đầu là token `[CLS]` do tokenizer thêm vào. Ở đây, ID 1 chỉ đóng vai vị trí đầu cho dễ minh họa.

## Ví dụ 3: Gắn bốn nhãn từ lên bảy subword

Câu gồm bốn từ: `An`, `đến`, `Hà_Nội`, `sớm`. Giả sử tokenizer tách `Hà_Nội` thành hai mảnh `Hà` và `##Nội`, rồi thêm `[CLS]` ở đầu và `[SEP]` ở cuối. Bài là nhận diện tên riêng, với nhãn `B-PER` cho người và `B-LOC` cho địa danh. Quy tắc ở đây: chỉ tính loss ở mảnh đầu tiên của mỗi từ.

```python
import math
import torch
from torch import nn

torch.set_num_threads(1)
tokens = ["[CLS]", "An", "đến", "Hà", "##Nội", "sớm", "[SEP]"]
word_ids = [None, 0, 1, 2, 2, 3, None]
word_labels = ["B-PER", "O", "B-LOC", "O"]
label_to_id = {"O": 0, "B-PER": 1, "B-LOC": 2}

def align_first_subword(word_ids, labels):
    result, previous = [], None
    for word_id in word_ids:
        if word_id is None or word_id == previous:
            result.append(-100)
        else:
            result.append(label_to_id[labels[word_id]])
        previous = word_id
    return result

aligned = align_first_subword(word_ids, word_labels)
for token, label in zip(tokens, aligned):
    print(f"{token:7s} -> {label}")

# Ở mỗi vị trí được chấm, lớp đúng có logit 2, hai lớp còn lại có logit 0.
logits = torch.zeros(len(tokens), 3)
for position, label in enumerate(aligned):
    if label != -100:
        logits[position, label] = 2
loss = nn.CrossEntropyLoss(ignore_index=-100)(logits, torch.tensor(aligned))
print("vị trí chấm / tổng token:", sum(x != -100 for x in aligned), "/", len(tokens))
print("loss:", round(loss.item(), 4))
assert aligned == [-100, 1, 0, 2, -100, 0, -100]
assert math.isclose(loss.item(), math.log(math.exp(2) + 2) - 2, abs_tol=1e-6)
```

```output
[CLS]   -> -100
An      -> 1
đến     -> 0
Hà      -> 2
##Nội   -> -100
sớm     -> 0
[SEP]   -> -100
vị trí chấm / tổng token: 4 / 7
loss: 0.2395
```

Danh sách `word_ids` cho biết mỗi subword thuộc từ thứ mấy. `[CLS]` và `[SEP]` không thuộc từ nào, nên là `None`, và nhận −100. Mảnh đầu của mỗi từ nhận nhãn của từ ấy. Mảnh thứ hai của cùng một từ, như `##Nội`, nhận −100.

Lưu ý `##Nội` nhận −100, chứ không nhận nhãn `O`. Nó vẫn là một phần của địa danh, chỉ là được bỏ qua khi tính loss. Gán nó là `O` sẽ dạy model rằng nửa sau của “Hà Nội” không phải địa danh. Bốn vị trí được chấm có cùng phân phối logit như ví dụ 1, nên loss cũng bằng 0.2395. Với tokenizer thật, hãy lấy ánh xạ này từ hàm `word_ids()` của tokenizer, đừng tự đoán dựa vào độ dài chữ hay dấu `##`.
